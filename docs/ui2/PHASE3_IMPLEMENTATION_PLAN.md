## 1. 阶段目标与范围

将原 Phase 2.5（发布准备）与 Phase 3（产品体验完善）合并为一个正式阶段：

**Phase 3：产品完善与发布就绪**

目标不是简单增加页面或视觉效果，而是让 React UI 2.0 在真实媒体库和真实桌面安装环境中具备可持续使用的核心能力，并形成可审查的发布候选结论。

本阶段分三个批次推进：

1. **A：基础可靠性与发布风险清理**——先消除已知风险，建立可安全迭代的基线。
2. **B：核心产品能力完善**——优先解决大媒体库、任务反馈等高频使用问题，再完善详情、搜索、首页和媒体源。
3. **C：集成回归与发布候选验收**——验证完整流程、安装产物、隐私和平台兼容性，输出是否具备发布条件的结论。

批次可以在独立工作分支上分步实施，但统一归属 Phase 3。每批必须有自己的测试记录、证据和回滚点；不能因阶段合并而跳过中间验收。

### 1.1 本阶段不代表的授权

Phase 3 完成不自动授权以下事项：

- 合并到 `main` 或其他正式主干；
- 创建正式版本 Tag、GitHub Release 或对外发布；
- 将 React UI 设为默认 UI；
- 删除 classic UI 或移除回退路径。

这些事项必须在 Phase 3 发布候选报告之后另行确认。

## 2. 已知基线与必须继承的约束

### 2.1 Phase 2 已交付基线

Phase 2 已具备：首页、电影/剧集分类媒体库、列表/网格基础展示、电影与按季详情、续播/播放接线、Ctrl/Cmd+K 标题搜索、媒体源页、任务页和隐私入口。默认仍为 classic；React 资源缺失或加载失败应回退 classic。

已知验证结果包括：

- CI Windows 构建成功，Node 22 环境执行 `npm ci`；
- CI 报告 249/249 Node 测试通过，compile、renderer typecheck、renderer build 和 Windows NSIS 构建通过；
- 真实媒体库约 17,000+ 条目；
- Phase 2 生产 CSP 保持严格：`connect-src 'none'`，生产不放开 `unsafe-inline` / `unsafe-eval`；
- 隐私密码的真实用户端到端解锁尚未完整实测；
- 扫描页面离开后，renderer 等待/监听可以取消，但不代表主进程扫描任务被取消；
- CI 生成的安装包需要在隔离环境完成安装与启动冒烟，不能仅以构建成功代替安装验证；
- Linux/macOS 真实运行验证仍有缺口；
- electron-builder 在 CI 环境出现过隐式 Release 上传尝试，预览构建必须明确禁止发布。

以上是计划编制时的基线；执行前必须以目标分支当前代码、workflow 和最新 CI 结果复核，不得把历史数字当作本次执行结果。

### 2.2 架构与兼容性边界

以下约束在 Phase 3 默认继续有效：

- Electron 桌面应用；React 仅作为本地打包 renderer，不引入独立 Web/PWA/CDN/生产 localhost 服务。
- 主进程、preload、SQLite、扫描、刮削、MPV 等既有业务尽量保持稳定。
- 不改变默认 classic；保留 React 加载失败回退。
- 保持 `contextIsolation=true`、`nodeIntegration=false`；`sandbox=false` 暂时维持，不能因安全加固目标直接强开 sandbox。
- 不随意扩大 preload IPC 白名单，不新增远程连接能力；生产 CSP 不放宽。
- 隐私模式的导航、数据查询、搜索、计数、缓存和异步响应都必须遵守旧 UI 的隐私裁剪语义。
- 不改 MPV、字幕、弹幕、smart_skip 等播放核心。
- 不做演职员 cast/crew；不新增独立媒体库健康页。
- 搜索快捷键保持 Cmd/Ctrl+K；`category=other` 仍对应 `/library/others`。
- 继续使用现有 TypeScript 编译与 Node `node:test` 测试体系；不得为了引入组件测试而替换现有测试体系。
- 不擅自迁移数据库 schema；不做未经评审的破坏性数据变更。
- 不执行 force push、reset hard、clean、合并 main、正式发布或打 Tag。

### 2.3 变更分级

| 等级 | 变更 | 处理方式 |
|---|---|---|
| L0 | React renderer 内部展示、状态管理、纯函数和现有 API 组合 | 可在本计划范围内实施 |
| L1 | 复用既有 IPC/event、修复 renderer 生命周期、CI 构建参数 | 先审查调用契约，再实施并补测试 |
| L2 | 新增 IPC、修改 preload 白名单、主进程任务状态协议、数据库 schema、跨进程取消协议 | 先提交 ADR/方案，暂停等待用户批准 |
| L3 | 修改播放核心、MPV/字幕/弹幕/smart_skip、默认 UI、发布/Tag/合并 main | 不属于本阶段授权范围 |

## 3. 执行流程与分支策略

### 3.1 分支

- Phase 3 计划文件所在分支：`docs/ui2-phase3-plan`。
- 实际代码实施必须从用户确认的 Phase 2 集成基线创建独立 feature branch；不要直接在文档分支开发。
- 批次 A/B/C 可以使用一个 Phase 3 feature branch，也可以按批次拆分短分支；无论哪种方式都必须保持提交可审查、可回滚。
- 不要将 `feature/ui2-phase2` 直接合并到 main。Phase 2 当前审查结论仅为允许进入集成审查/集成分支，不等于 main 合并授权。
- 开始代码实施前，先确认实际集成目标分支、HEAD、工作区状态和 Phase 2 是否已按用户决策集成；若状态与本计划基线不同，先更新计划，不要猜测。

### 3.2 每个任务的固定循环

1. 读相关实现、preload API、主进程 handler、旧 UI 对应行为和现有测试。
2. 输出简短实施方案：改哪些文件、是否触及 IPC/DB、隐私影响、风险与回滚。
3. 按任务范围实施；不顺手重构无关代码。
4. 运行相关测试，再运行阶段完整门禁。
5. 在真实 Electron 环境验收关键路径；不能只用 DOM 存在性断言。
6. 更新本计划对应清单和验收记录；记录未覆盖项。
7. 停止并交付结果，等待用户确认后再进入下一批。

### 3.3 通用门禁

按仓库当前 scripts 和 CI workflow 执行，至少包括：

```bash
npm ci
npm run compile
npm test
npm run renderer:typecheck
npm run renderer:build
```

如果 CI 使用不同的受支持 Node 版本或额外检查，以仓库 workflow 为准并记录差异。对安装包任务还必须执行对应平台的 electron-builder 构建和安装后启动测试。

每批验收记录必须包含：分支/commit、改动文件、行为变化、命令及结果、真实 Electron 证据、隐私/键盘/窗口检查、已知缺口、回滚方式和待用户决策。

## 4. 批次 A：基础可靠性与发布风险清理

**目标：** 在扩大产品能力前，先明确隐私、任务生命周期和发布流水线的真实边界，避免把历史验收盲区带入新功能。

### A-01 隐私库完整端到端验收（P0）

**范围**
- 从普通库进入隐私库；
- 正确密码解锁；
- 错误密码反馈；
- 锁定/退出隐私库；
- 锁定后路由回到安全页面；
- 浏览器历史、搜索弹层、详情页、媒体源和任务页不能残留私有内容；
- 解锁/退出过程中快速重复点击、切页、关闭窗口；
- 隐私锁定状态下刷新/重新进入应用的行为。

**实施要求**
- 首先审查既有 `library:privacy-*` IPC 契约和旧 UI 等价行为。
- 真实密码只在用户本机交互测试时使用；不得要求用户把密码发给 OpenCode/ChatGPT，不得写入日志、截图、fixture、测试文件或提交。
- 自动化测试使用临时测试密码/隔离数据目录/可注入测试 fixture；测试后销毁临时数据。
- 重点检查异步请求过期响应、缓存和订阅是否可能在锁定后重新写入私有数据。
- 若需要新增 IPC 或改变主进程隐私协议，先提交 ADR 并暂停，不在本任务自行扩展。

**验收**
- 正确密码能解锁；错误密码不解锁且反馈清楚。
- 锁定后私有页面、搜索结果、详情数据和媒体源信息均不可见。
- 锁定/退出后不能通过浏览器后退或旧异步响应回到私有数据。
- 快速重复操作不会产生并发状态错乱。
- 测试不包含任何真实用户密码或真实私有数据。

### A-02 扫描/刮削生命周期与重复触发边界（P0）

**范围**
- 从任务页触发扫描/刮削；
- 请求进行中离开页面；
- 返回任务页；
- 在旧任务仍运行时再次触发；
- 连续点击、路由快速切换、窗口关闭；
- 成功、失败、超时和 IPC listener 清理。

**实施要求**
- 明确区分“renderer 停止等待/取消订阅”和“主进程实际停止扫描”；UI 不得将前者表述为后者。
- 先审查现有 in-flight 锁、AbortSignal、事件订阅、一次性 reply listener 和主进程任务语义。
- 对扫描和刮削分别画出状态转换，确认离页后再次进入是否会误触发重复任务。
- 仅在现有契约允许时修复 renderer 防重入/状态恢复/监听清理。
- 不自行新增主进程取消任务接口；如果确实需要真正取消主进程扫描，单独提出 ADR，等待批准。

**验收**
- 离页不遗留 renderer listener。
- 同一任务运行期间重复点击不会创建并行等待或重复触发。
- 重进任务页时 UI 能如实表示“正在运行/状态未知/已完成”，不得凭空显示进度。
- 错误、超时和卸载路径都能清理监听。
- 通过行为测试覆盖关键状态转换，不只依赖静态源码断言。

### A-03 CI 预览构建禁止隐式发布（P0）

**范围**
- 审查 `.github/workflows/` 下全部构建/Release workflow；
- 审查 package scripts、electron-builder 配置、发布环境变量和 workflow_dispatch 条件；
- 区分 PR/branch preview build 与正式 Release job。

**实施要求**
- 对预览构建显式使用 electron-builder 的 `--publish never`（或经验证的等价配置），不能依赖“当前条件下通常会跳过”。
- 正式发布只能由独立、明确授权的 Release workflow 负责。
- 检查 workflow 权限最小化；普通 CI 不应拥有不必要的 contents write / release 权限。
- 不在本任务创建 Release，不上传正式资产，不改版本号。
- 对每一种构建入口验证最终执行命令确实禁止发布；仅修改一个 workflow 而遗漏 package script/矩阵入口不算完成。

**验收**
- PR、普通 push、手动 preview 构建均不会创建 Release 或上传 Release asset。
- CI 日志明确显示 publish disabled/never。
- Release workflow 仍需显式手动授权或受控条件触发；本阶段不实际执行发布。

### A-04 CI 安装包隔离安装与启动冒烟（P0）

**范围**
- 下载 Phase 3 对应 CI 产物；
- 在隔离 Windows VM/测试机或独立测试环境安装；
- 启动、关闭、卸载；
- 检查安装包资源、主进程启动、classic 默认壳、窗口控制和回退行为。

**安全要求**
- 不覆盖用户当前正常安装的 v3.2.9。
- 不复用/迁移真实用户配置目录，不直接使用真实媒体库和隐私数据。
- 优先使用独立 Windows 用户、隔离 VM 或独立安装目录；如安装器强制写入共享目录，先设计隔离方案。
- 如必须使用真实机器，先备份相关用户数据并记录恢复步骤；未经用户确认不得覆盖既有安装。
- 安装测试失败时保留日志与产物，不做破坏性清理。

**验收**
- 安装成功、启动成功、主窗口正常、默认 classic、基础媒体源/媒体库读取不崩溃。
- 关闭和卸载正常。
- 记录安装包 SHA256、CI run、commit SHA、OS 版本和测试环境。
- 明确区分“CI 构建成功”与“安装后运行成功”。

### A-05 Windows 回归与跨平台缺口清单（P0）

- 在 Windows 上运行 Phase 2 既有核心路径：启动、窗口控制、媒体库、详情、播放接线、隐私入口、媒体源、扫描/刮削触发、classic fallback。
- 不把播放按钮的 fire-and-forget 请求显示成播放成功；既有协议没有回包时保持如实反馈。
- 记录 Linux/macOS 当前可构建性、运行环境和依赖限制；能运行则做冒烟，不能运行则标记未验证和阻塞原因，不得写“跨平台通过”。
- 检查 macOS 原生交通灯与 Windows/Linux 自绘窗控边界不回归。

## 5. 批次 B：核心产品能力完善

**目标：** 优先解决真实大库使用中的可用性和反馈问题，再完善详情、搜索、首页和媒体源。避免先做视觉装饰。

### B-01 媒体库分页、排序、筛选与大库性能（P0，优先开发）

**现状问题**
- 当前分类计数依赖多次 catalog 查询，查询上限可能导致计数不完整（已知 G1）。
- 真实媒体库规模为 17,000+ 条目；Phase 2 当前卡片列表和数据获取方式尚未证明适合大库持续使用。

**实施步骤**
1. 梳理 catalog API 的排序、limit、offset/cursor、分类筛选、隐私过滤、稳定排序和总数语义。
2. 记录当前实际数据路径：页面 → renderer service → preload bridge → IPC → main handler → store/query。
3. 先用现有接口实现 renderer 分页/增量加载；确认现有接口无法提供稳定分页或准确总数时，停止并提出 IPC/DB ADR，不得通过反复拉取全部数据伪造分页。
4. 设计可恢复的分页状态：切分类、筛选、排序、搜索、隐私锁定/解锁时清理或重置游标。
5. 评估虚拟列表；只有真实性能测量证明 DOM 节点数量是瓶颈时才引入，避免无依据增加依赖。
6. 明确分类计数口径：准确总数、当前加载数、估算数不可混用；不能准确获取时应清楚标注。

**功能范围**
- 分页/加载更多或经测量确认的虚拟列表；
- 排序：至少按标题和最近添加/更新时间（前提是数据字段真实存在）；
- 筛选：仅使用真实数据字段；
- 保持网格/列表视图；
- 保留四分类及 `other → /library/others`；
- 空状态、加载状态、失败重试、快速切换时过期请求保护；
- 隐私模式独立分页和筛选，不允许普通库缓存污染隐私库。

**性能验收**
- 使用脱敏的 17,000+ 条目数据或等价规模 fixture。
- 记录首次可交互时间、首屏条目数、分页耗时、内存/DOM 节点数量、连续翻页稳定性。
- 建议验收目标：首屏不要求一次性加载全库；连续翻页不出现明显卡死/重复/丢失；排序和筛选结果可重复；目标阈值先在当前机器建立基线，再由用户确认，不得伪造统一毫秒指标。
- 验证大库下分类计数准确性或明确说明计数口径。

**可能涉及的代码区域（执行前以仓库为准）**
- `src/renderer/pages/Library*` 或实际媒体库页面；
- `src/renderer/services/` 中 catalog/library service；
- 相关 renderer 类型、纯函数与 node:test；
- 只有批准后才修改 main IPC handler / store 查询。

### B-02 任务中心完整化（P0）

**目标**
把当前“触发任务 + 完成摘要”的基础任务页提升为可信的任务工作台，但不虚构主进程未提供的数据。

**第一步：能力盘点**
- 列出现有扫描/刮削触发通道、进度事件、结果事件、历史数据和失败信息。
- 明确每个字段来源、更新频率、任务唯一标识、生命周期、是否跨页面/跨应用重启持久化。
- 区分实时状态、最近一次结果和历史记录。
- 不把 renderer 自己的 loading 状态当成主进程真实任务状态。

**实施范围**
- 任务列表与状态标签；
- 有真实事件时显示真实进度；无真实进度时显示“正在执行/等待结果/状态不可用”等诚实状态；
- 成功/失败结果摘要与错误信息（过滤敏感路径、凭据和隐私数据）；
- 最近任务历史；
- 重试入口仅用于可安全重试、已知幂等的任务；
- 重复触发保护；
- 离页/重进后状态恢复（受现有主进程能力限制）；
- 任务结束、失败、超时后 listener 和 loading 状态正确清理。

**不在默认授权内**
- 新增持久化任务表；
- 修改 SQLite schema；
- 新增主进程任务管理协议或 IPC；
- 主进程真正取消扫描/刮削；
- 自动恢复会改变文件系统的中断任务。

上述需求如确有必要，先提交 ADR，描述数据模型、兼容性、隐私、迁移和回滚，等待批准。

**验收**
- 扫描、刮削分别验证开始、进行中、完成、失败、超时、离页、重进和重复点击。
- 所有状态都能追溯到真实数据来源。
- 隐私模式不会泄露私有路径或结果。
- 对无法观测的状态明确显示限制，不显示伪造百分比。
- 测试覆盖状态转换和监听清理。

### B-03 电影/剧集详情与多版本体验（P1）

**范围**
- 保持电影详情和剧集按季详情已有结构。
- 审查现有详情 DTO 的 `versions` 数据，补齐同电影多版本展示/切换（已知 G5），前提是播放接口对指定版本的语义已经存在且经过验证。
- 展示可用的真实元数据、文件信息、观看状态、续播位置。
- 剧集季/集切换和续播入口一致。
- 空元数据、缺海报、缺文件、损坏记录有明确状态。
- 详情异步加载需要取消/过期保护。

**约束**
- 不新增 cast/crew。
- 不修改 MPV/播放核心，不伪造播放结果。
- 如果播放接口无法指定具体版本，先列出协议缺口并提交 ADR；不要在 UI 上做一个实际无效的版本选择器。

**验收**
- 多版本列表与后端真实版本一一对应，切换后播放请求参数正确。
- 续播、已观看、未观看、缺失元数据状态正确。
- 隐私模式和普通模式数据隔离。
- 电影、剧集、季详情的路由返回与快速切换无陈旧数据。

### B-04 全局搜索完善（P1）

**当前边界**
Phase 2 搜索主要是标题搜索，结果上限 50；文件名搜索尚未支持（已知 G4）。

**范围**
- 保留 Cmd/Ctrl+K 全局快捷键和现有弹层交互。
- 评估标题、剧集名、文件名搜索；只有后端真实支持的字段才可展示为可搜索范围。
- 增加清晰的搜索范围说明、空结果、加载、错误和清除状态。
- 如数据能力允许，支持分类过滤和排序。
- 记录最近搜索（仅当隐私语义和存储位置安全时）；隐私搜索历史必须独立或不持久化。
- 防止快速输入时旧响应覆盖新关键词；支持 Escape 关闭和键盘导航。

**验收**
- 搜索范围文案与真实能力一致。
- 结果可正确跳转详情，快捷键在输入框、弹窗和隐私状态下无冲突。
- 隐私搜索不进入普通历史或普通缓存。
- 不在 UI 中声称支持尚未实现的文件名/模糊/全文搜索。

### B-05 首页数据准确性（P1）

**范围**
- 首页继续使用紧凑页头，不引入 310px 大 Hero。
- 汇总卡片/最近添加/继续观看数据必须来自真实接口和明确时间范围。
- 避免用多次不完整 catalog 查询计算总数；与 B-01 共享准确计数口径。
- 空库、未扫描、部分加载、隐私锁定和请求失败状态清晰。
- 首页查询应轻量，避免启动时拉取 17,000+ 全量数据。

**验收**
- 所有数字可追溯到接口及口径。
- 首页加载不会阻塞应用启动或触发全量扫描。
- 隐私库内容不会进入普通首页摘要。

### B-06 媒体源管理完善（P1）

**范围**
- 继续使用 Phase 1 已有测试连接、更新源、历史等能力和既有脱敏规则。
- 完善源详情、连接测试反馈、单源重扫状态、错误信息和历史记录。
- WebDAV 凭据不得进入 renderer 日志、任务摘要或 UI 可见 URL。
- 隐私模式下路径/URL 继续隐藏。
- 只有既有 IPC 支持的动作才提供按钮；不扩展 SMB 客户端或新增扫描协议。

**验收**
- 本地源/WebDAV 源的显示、测试、更新、重扫行为与真实接口一致。
- keep/replace/clear 凭据语义不回归。
- 历史只展示白名单 DTO 字段。
- 隐私模式下敏感字段完全隐藏。

### B 批次开发优先顺序

1. B-01 媒体库分页/大库性能；
2. B-02 任务中心；
3. B-03 详情与多版本；
4. B-04 搜索；
5. B-05 首页；
6. B-06 媒体源。

B-01 和 B-02 是核心优先级。不得先投入大量时间做装饰性 UI，再把分页/任务状态推迟。

**批次 B 交付物**
- 每个 B 项一份实现记录和验收记录；
- 大库性能基线与前后对比；
- 任务状态模型/数据来源说明；
- 如需 L2 变更，独立 ADR 和用户批准记录；
- 更新后的 UI 截图与真实 Electron 验收结果。

**批次 B Gate**
- 大库分页/筛选/排序可用，计数口径诚实且隐私隔离通过。
- 任务中心状态真实、可追溯，无伪造进度或成功状态。
- 详情多版本只在播放契约支持时开放。
- 搜索范围与实际能力一致。
- 首页和媒体源无隐私泄漏、无旧功能回归。

## 6. 批次 C：集成回归与发布候选验收

**目标：** 将 A 的可靠性成果和 B 的产品能力放在同一真实桌面环境中验证，产出明确的发布候选结论。

### C-01 完整业务流程回归

至少覆盖以下流程：

1. 首次启动/已有配置启动；
2. 默认 classic 启动和 React 显式启用；
3. React 资源缺失/加载失败回退 classic；
4. 首页 → 分类库 → 筛选/排序/分页 → 详情 → 返回；
5. 电影多版本选择（若已实现）与播放请求；
6. 剧集 → 季 → 集 → 续播；
7. Cmd/Ctrl+K 搜索 → 结果 → 详情；
8. 媒体源测试、更新、单源重扫；
9. 扫描/刮削任务状态与历史；
10. 隐私库正确解锁、错误密码、浏览、搜索、退出/锁定；
11. 锁定后浏览器后退、旧异步响应、重进页面；
12. 关闭窗口、重新启动、配置与任务状态恢复（仅对现有持久化能力做断言）。

### C-02 大库性能与稳定性

- 使用脱敏 17,000+ 条目真实规模或等价 fixture。
- 记录启动到首屏、分类切换、分页、排序、筛选、搜索、详情打开的时间。
- 连续翻页、快速切换分类、反复搜索，检查重复/遗漏/旧响应覆盖。
- 记录 renderer 内存、DOM 节点和主进程资源趋势；至少比较优化前后同一环境结果。
- 不以单次主观“感觉流畅”作为验收结论。

### C-03 安全与隐私回归

- 生产 CSP 不得放宽；检查打包产物无远程脚本、localhost/ws 连接和不必要内联代码。
- 隐私模式覆盖首页、媒体库、搜索、详情、媒体源、任务中心、路由历史和异步缓存。
- 凭据、密码、私有路径不进入日志、截图、CI artifact、错误报告和测试 fixture。
- IPC sender validation、navigation 限制和 preload 白名单不回归。
- `sandbox=false` 仍是已知架构债务；本阶段只做兼容性评估，不直接开启。

### C-04 安装包和平台矩阵

| 平台 | 最低验收 |
|---|---|
| Windows x64 | CI 安装包隔离安装、启动、默认 classic、窗口控制、卸载；React 显式验证只在受支持验证路径进行 |
| macOS x64/arm64 | 对应架构构建与启动冒烟；原生交通灯、签名/entitlements 约束记录 |
| Linux x64/arm64 | AppImage 对应架构构建与启动冒烟；窗口控件和依赖记录 |

平台环境不可用时，必须标记“未验证”，不得用交叉编译成功代替真实运行通过。记录平台、架构、OS 版本、Node 版本、Electron 版本、artifact SHA256、构建 run 和结果。

### C-05 发布候选审查包

输出：
- Phase 3 总验收报告；
- 各平台构建/运行矩阵；
- 大库性能前后对比；
- 隐私与安全回归记录；
- 未解决缺口及严重度；
- 安装包 SHA256 与 CI run；
- 回滚说明；
- 是否建议进入正式发布审批的明确结论。

**批次 C Gate**
- 核心业务流程全通过。
- 无已知 P0/P1 隐私、安全、数据完整性或启动阻塞问题。
- Windows 安装后冒烟通过。
- Linux/macOS 明确标注通过/未验证/阻塞，不夸大覆盖范围。
- 生产 CSP、classic fallback、默认 classic 和旧业务回归通过。
- 发布候选报告得到用户审阅后，才进入独立的正式发布决策。

## 8. 回滚策略

- 每个批次保持独立 commit，优先小步提交。
- renderer 功能以 feature flag/路由入口隔离；回滚时可恢复到 Phase 2 UI 行为。
- 默认 classic 始终保留；不得将 React 设为默认作为“临时验证”。
- 不做 DB migration；若后续经批准实施 migration，必须单独提供备份、向前/向后兼容和恢复演练。
- 不修改 MPV、字幕、弹幕、smart_skip 等播放核心。
- CI 发布风险修复应先在分支验证 preview 不发布，再进入正式 workflow。
- 安装包测试在隔离环境执行，避免污染用户当前安装和数据。
- 任何任务失败都不得使用 force push、reset hard 或 clean 掩盖问题。
